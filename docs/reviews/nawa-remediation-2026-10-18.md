# Nawa review remediation — 18 October 2026

This records the implementation following the [comprehensive review](nawa-comprehensive-review-2026-10-18.md). It preserves the existing chat work and authored document content. The thirteen findings are addressed by the changes below; the dependency finding includes explicit mitigations for three advisories that have no upstream patch.

| Finding                        | Change and verification                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1 — Interrupted PPTX saves    | ZIP output streams into an exclusive file beside the destination, is flushed, and replaces the destination only after completion. There is no in-place fallback. Failed streams preserve the original; failed replacement preserves a completed recovery copy. Tests inject ENOSPC, a locked rename and conflicts. Existing save-ordering tests still verify edits during saves remain dirty.                                                                                   |
| R2 — Source encoding           | Native Markdown/text/config and HTML use the same strict decoder, encoder and per-view source session. UTF-8, BOM, UTF-16 LE/BE, Arabic/Japanese and uniform line endings round-trip. Invalid input is rejected. Unit tests and real Electron read/save tests verify byte identity.                                                                                                                                                                                             |
| R3 — External changes          | SHA-256 revisions are checked before staging and again before replacement. Markdown, HTML and Slides retain the last opened/committed revision. Presentation receipts carry the hash of the actual streamed bytes. Stale saves fail with reload/Save As guidance; tests preserve the external writer's bytes and cover concurrent editors.                                                                                                                                      |
| R4 — Word renderer retention   | Closing a Word tab unloads its document to `about:blank` before closing WebContents. This avoids the previous close freeze. The native test repeats open/close five times, verifies WebContents return to baseline after each close and checks shell responsiveness.                                                                                                                                                                                                            |
| R5 — Preview chat outcomes     | Completed, cancelled, output-limited, turn-limited and empty results have explicit outcomes. Incomplete answers offer retry and persist their outcome. Only completed question/final-answer pairs matching the current source fingerprint enter model history. Stop and close/reopen persist cancellation; late callbacks cannot change a newer request. Refreshing a changed file rebuilds the active model context. Native tests inspect requests to verify these boundaries. |
| R6 — HTML networking           | Local HTML scripts/assets still work; remote content is blocked by default. A localized per-file control enables or revokes remote content. CSP, request filtering and permission restrictions cover preview/presentation surfaces. Shared session policies compose with the directory-stage guard. Tests verify default block, opt-in, revocation and guard composition. README and privacy claims now match behavior.                                                         |
| R7 — Keyboard resizing         | All six editors and preview chat use the shared resizer, keyboard arrows, Home/End, focus styling, accessible name, controlled-panel ID and announced width limits. Spreadsheet grid resizing uses the same contract. Native Arabic tests resize every editor and the preview, and verify physical layout is retained.                                                                                                                                                          |
| R8 — Placeholder contrast      | A semantic placeholder token is provided in light, dark and system-dark themes. Contrast tests require at least 4.5:1 against the application and panel backgrounds.                                                                                                                                                                                                                                                                                                            |
| R9 — Shared contracts          | File transactions, text source sessions, terminal chat outcomes, safe restored preview history, localized status strings and panel resizing have shared implementations with regression tests. Editor-specific model and save-receipt behavior remains in each adapter. The native reliability suite tests common behavior across adapters.                                                                                                                                     |
| R10 — Bundle cost              | All seven production renderers now explicitly enable esbuild minification. Raw built JavaScript falls from 56.84 MB to 31.48 MB (44.6%). Per-app entry and total-JS budgets fail CI on regressions. Sheets' locale-named chunks are hyphenation data from Univer's render engine, not unused interface translations; they remain available for document layout.                                                                                                                 |
| R11 — Windows release coverage | A native Windows workflow builds every editor, checks budgets/security, runs the reliability suite, builds an isolated unsigned installer, then validates installed runtime resources, CLI, upgrade/uninstall, OpenDocument flows and the same reliability suite against the installed executable. Artifacts include test reports and installer/runtime logs.                                                                                                                   |
| R12 — Dependency triage        | `http-cache-semantics` is updated to compatible patched 4.3.0. Three remaining upstream advisories have version-specific mitigations and a 2026-11-17 review deadline. CI rejects new advisories, version drift, critical severity, registry failures, missing evidence and expired mitigations. See the [dependency security record](dependency-security-2026-10-18.md). This is not a zero-advisory claim.                                                                    |
| R13 — Localized states         | English/Japanese/Arabic dictionaries now cover loading history, empty history, stop/interruption, incomplete output, no reply and transport failures. Late network errors use the current language after a switch. Dictionary and live component tests cover these states without adding unstable translation functions to effect dependencies.                                                                                                                                 |

## Permissive image runtime

The existing license gate rejected Sharp's LGPL native packages. The user chose replacement while retaining the permissive-only production dependency rule. The gate is unchanged and now passes.

Previews and local OCR now share Skia (`@napi-rs/canvas`) with the existing MIT-licensed UTIF2 decoder for TIFF. PNG/JPEG/WebP/GIF/BMP/TIFF support, EXIF/TIFF orientation, first-frame decoding, transparency, white JPEG compositing and bounded vision resizing are covered. Inputs retain the 20-million-pixel and 64-MiB limits; TIFF metadata traversal, DEFLATE expansion and embedded JPEG dimensions are bounded before decoding. Source bytes are preserved.

The pinned Transformers.js code is built into a private text-only runtime. Its image backend is replaced at build time by an explicit unsupported-task boundary; Nawa's separate image preview/OCR/vision support remains available. The original model, tokenizer, q8 weights, mean pooling, normalization and model revision are unchanged. An integration check downloaded the pinned model and verified identical token IDs and normalized 384-dimensional vectors for English, Arabic and Japanese against upstream.

Sharp remains a transitive **development/build-test** dependency of the upstream Transformers.js package, pinned to the reviewed version. Nawa neither loads nor distributes it at runtime. The embedding build and packaging hook inspect the bundler manifest for forbidden Sharp/libvips inputs or external imports. The installed-payload test also rejects their package directories in app.asar and external resources. Third-party notices retain attribution for the bundled upstream text code and omit its excluded image backend. No LGPL exception was added.

The updated shell suite passed 1,279 tests. Additional focused runs passed the animated-GIF regression, three packaging guard regressions, two control timeout regressions and the interrupted-history regression. The existing two preview-chat E2E tests also passed, covering actual vision inputs, OCR, separate histories and three-language pane placement.

An installed legacy Word opening check exposed a readiness-budget mismatch: conversion may take 90 seconds, while the control bridge gave up after 20 seconds. Import-only Office formats now receive a 120-second readiness budget and matching 130-second client/server response budgets. Modern documents retain their 20-second readiness limit. Virtual-time tests demonstrate that an imported document becoming ready after 25 seconds succeeds while the same delay still times out for a modern document. The nine CLI control tests also pass. Installer failures now capture the failed sample, renderer state and bounded stderr for diagnosis.
